# 当前能力边界与降级策略

## 评估结论

- **AI 输出可能错误，始终需要教师确认。** 报告初始状态是 `proposed`，界面和 Mattermost 卡片都标注“AI 基础评估”；系统不把模型分数直接当作最终教学裁决。
- 模型即使返回结构合法 JSON，也可能存在事实错误、遗漏或偏差。结构校验只能保证字段、范围和部分语义一致性，不能证明结论正确。
- 分数等级按固定阈值归一化（A≥90、B≥75、C≥60、D<60），但 rubric 本身是否合理仍由教师负责。

## 答案与题目

- **源代码只作为文本评审，不会在沙箱中执行。** 系统不编译、不运行学生代码，不测时间/空间资源，也不接触宿主文件、网络或系统调用。
- **模糊题目、不完整答案和缺失 rubric 会降低置信度。** 无法确定时应输出 `unable_to_determine`、限制说明并转人工，而不是猜测隐藏意图。
- 文本/Markdown/代码答案上限 50,000 字符；结构化 JSON 另有 100 KiB、深度 32、节点 10,000 的限制。超限输入会拒绝，不会静默截断为可评估答案。
- **不宣称支持抄袭检测、文件 OCR 或隐藏测试执行。** 当前也不解析 PDF/Office 附件、图片手写答案、压缩包或外部 Git 仓库。
- 学生 Prompt Injection 会作为不可信答案数据传给 Provider；系统提示要求忽略其中的指令，但真实模型防护不是数学证明，教师仍需复核。

### 老师测试数据集的使用边界

老师提供的 CSC3100 Assignment 1 模拟数据集包含 20 人名册、19 份上传记录、16 份格式有效 ZIP、3 份异常 ZIP、1 次迟交、1 人缺交、评分 rubric、公开/隐藏用例以及预期模拟结果。它保留为外部 QA 和后续能力扩展的参考数据，不是当前应用已导入的业务数据，也不构成已通过的新增验收证据。

- 当前 v1 不摄入 ZIP 提交、CSV 名册或 submission manifest，不隔离/检疫异常压缩包，也不会从这类数据集元数据自动建立迟交、格式无效、缺交或补交语义。现有作业汇总仍会把每名没有最新提交的 active 学生标为未交；这里缺少的是数据集导入与状态映射能力，不是一般性的未交汇总。
- 当前 v1 不执行公开或隐藏代码测试，不编译学生程序。Web 支持文本、Markdown 和代码文本提交，Mattermost `/hw submit` 创建文本提交，REST API 还支持结构化 JSON；代码均只作文本评审。这个边界不限制作业要求允许的提交形式。
- 当前 v1 不检测 AI 写作。数据集中的 AI-writing risk 只是模拟的教师复核提示，不是作弊证明，不能触发自动扣分或自动裁决。
- 将来若增加批量摄入，必须先设计压缩包解压隔离、路径穿越/解压炸弹防护、文件类型与大小限制、名册身份匹配、迟交规则、隐藏用例保密和逐项人工复核；当前版本不暗示这些安全能力已经存在。

## Provider 外部依赖

- **真实 Provider 的可用性、限流、成本与延迟属于外部依赖。** 网络错误、超时、429、模型下线、账号余额、供应商协议变化都可能令 job 失败。
- OpenAI-compatible 仅表示使用 Chat Completions 风格请求与结构化响应契约，不承诺兼容任何未测试厂商的私有扩展。
- 非法输出最多尝试三次（初次 + 两次修复）。持续非法时系统保存 `validation_exhausted` 证据，不生成“看似成功”的占位报告。
- Provider 故障不会删除学生提交；教师可在汇总看到安全错误类别后决定重试。公共响应和日志不会回显上游私密错误正文。
- 现场验收建议使用 `AGENT_PROVIDER=mock` 与种子报告；mock 证明系统流程可重复，不证明真实模型质量。

## Mattermost

- **Mattermost 演示认证是简化的本地集成。生产必须使用 HTTPS、轮换密钥并限制来源。** 需要同时保护 Slash Token、Bot Token、Action Secret、JWT Secret、demo setup key 和数据库密码。
- development/test 的 demo binding route 通过 `X-Demo-Setup-Key` 绑定预置账号，只用于本地启动；staging/production 不注册该路由。生产身份同步、离职/禁用流程和组织目录集成不在当前范围。
- Slash 请求使用 Mattermost 提供的共享 Token，不包含时间戳或第三方签名协议；安全依赖 HTTPS、Token 保密、严格字段/大小校验和不可变 User ID 绑定。
- Bot 通知使用持久 outbox 和 at-least-once 语义。发送成功但进程在记录 post ID 前崩溃的极端窗口可能重复发帖；系统不宣称 exactly-once。
- Bot Token 权限需由管理员最小化；配置脚本创建用户、Team、Channel、membership 与 Slash Command，但不会自动创建高权限 Bot。
- 当前只支持单个 `/hw` trigger 和一个本地课程演示 Team/Channel；没有多租户配置控制台。

## 角色与权限

- **角色模型能区分教师、学生路径，但不是院校级权限系统。** 它没有院系/课程/班级/助教层级、选课名单、组织委派、细粒度 rubric 权限或集中式 RBAC 管理。
- 当前汇总把数据库中的所有 active student 视为每一份作业的全局学生池；管理员或教师新建的 active 学生会立即计入所有作业汇总。这适合单课程演示，不是正式教务选课关系。
- 教师可以查看所有作业/提交/报告，学生只能看已发布/关闭作业、自己的提交和报告。`admin` 只管理本地账号，不自动拥有教师业务权限，也不是 Mattermost 服务器管理员；本地管理员不会自动创建或绑定 Mattermost 身份。
- 管理员可以创建教师或学生，教师只能创建学生；任何应用调用方都不能创建管理员，学生不能调用账号管理。管理员不能读取作业、提交、评估或审核数据。
- 当前账号管理 v1 每次只创建一个 active 本地账号，不提供自助注册、批量创建、密码重置、账号停用/重新启用、编辑或删除能力；需要此类生命周期操作时应通过受控运维流程处理。
- 本地账号创建不会同步 Mattermost 用户或自动绑定身份；需通过受控的显式绑定流程关联 Mattermost 返回的不可变 User ID。不要把本地 `admin` 误当成 Mattermost 服务器管理员。
- 用户名为 3–64 位规范化小写 ASCII 标识，密码为 12–128 个字符且不能与用户名相同；用户名冲突返回 HTTP `409`。文档演示凭据不得用于共享或生产环境，真实密码、Token 和 API Key 不应出现在命令行或共享 shell history。
- JWT 是本地账号登录结果，没有 SSO、MFA、刷新 Token、会话撤销列表或设备管理。

## 数据、扩展性与运维

- PostgreSQL 是唯一业务真相；Redis 仅作 Celery broker。恢复 Redis 不会恢复尚未提交的内存任务，但数据库 outbox 可重驱已提交任务。
- 作业汇总假设 active student 不超过 10,000；列表/时间线采用上限和分页，尚未做超大院校规模压测。
- 批量评估有明确单批上限；超限返回冲突，需要分批或扩展任务编排。当前没有用户可配置的优先级、配额和公平调度。
- 当前不提供对象存储、附件生命周期、跨区域灾备、备份恢复自动化、指标仪表盘、集中日志或告警系统。
- 迁移 gate 能协调新版业务事务，但首次从 pre-gate 版本升级仍要求停止旧连接；命令不会自动杀死未知进程。
- Mattermost、API、worker 与 Web 的真正生产高可用、水平扩展、TLS 终止和 secret manager 配置未包含在本地验收包中。

## 已验证与未验证的界线

已在本地隔离 PostgreSQL 上实跑后端验收、真实 FastAPI/Vite/Playwright 流程及 URL-encoded Mattermost adapter；账号管理版本也已在 Docker 29.6.2 / Compose v5.3.1 中完成迁移、种子、API/Web 健康检查和专用 Playwright 流程。真实 Mattermost 10.5 交互与完整 `make demo-full` 仍未在本轮实跑，不能据此宣称通过。详情见 [test-results.md](test-results.md)。

## 演示降级

- Provider/网络故障：直接打开 `HW-0001` 的 94/A、72/C、35/D 种子报告；不把失败掩饰为实时结果。
- Mattermost 不可用：展示 [mattermost-setup.md](mattermost-setup.md)、adapter E2E 与 REST 状态一致性，不声称真实容器已运行。
- Web 不可用：先执行 `make health`，再使用 [api-examples.md](api-examples.md) 和本地 Playwright 报告；不删除或终止未知占用进程。
